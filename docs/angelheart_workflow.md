# AngelHeart 当前业务流程

本文只描述当前运行路径。群聊的状态机与调度细节以 [群聊双防抖与状态机](architecture/group_dual_debounce_state_machine.md) 为准。

## 一、参与模型

### 私聊

- 私聊消息写入 `ConversationLedger`。
- 私聊不经过秘书、不使用群聊防抖，也没有离场/在场状态。
- 请求由 AstrBot 主框架直接处理或排队；后到消息不能注入已经运行的子代理。

### 群聊

群聊只有两态：

- **离场（`NOT_PRESENT`）**：普通消息只入账。被 @ 或命中点名词才会进入在场；若开启离场应答，复读或密集发言可触发一次回复，但回复后仍保持离场。
- **在场（`OBSERVATION`）**：只有被 @ 或命中点名词后才进入；在场超时后，收到下一条消息时回到离场。

`SUMMONED` 与 `GETTING_FAMILIAR` 仅是旧路径兼容枚举，不属于当前业务状态。复读或密集聊天的离场应答只回复一次，不会形成持续参与路径。

## 二、群聊主流程

```mermaid
flowchart TD
    A[收到群聊消息事件] --> B[写入 ConversationLedger]
    B --> C{当前状态与消息是否点名}
    C -->|离场且未点名| D{命中已开启的离场应答条件？}
    D -->|否| E[只入账并停止事件]
    D -->|是| F[建立一次性回复等待]
    C -->|离场且点名| G[进入在场]
    C -->|在场| H[更新群聊等待账本]
    G --> H
    H --> I{消息类型}
    I -->|点名消息| J[助理防抖]
    I -->|在场的普通消息| K[秘书巡检]
    J --> L[旧边界事件 KILL]
    K --> L
    F --> L
    L --> M[最后边界事件等待到期]
    M --> N{同会话已有秘书调度？}
    N -->|是| O[保留边界事件并完整重计]
    N -->|否| P{助理忙碌或（非离场应答且）助理休息未结束？}
    P -->|是| O
    P -->|否| Q{普通巡检且精力不足？}
    Q -->|是| O
    Q -->|否| R[占用同会话秘书调度]
    R --> S[重建当前上下文]
    S --> T{离场一次性应答？}
    T -->|是| U[生成一次性回复策略]
    T -->|否| V[判断是否需要接话]
    V -->|不回复| W[记录不回复并释放秘书单飞]
    U --> X[交给助理并立即释放秘书单飞]
    V -->|回复| X
    X --> Y[助理生成并发送回复]
    Y --> Z{离场一次性应答？}
    Z -->|是| AA[保持离场，启动离场应答休息]
    Z -->|否| AB[进入或保持在场，结算能量并完成助理休息]
```

## 三、双防抖与单飞

- **助理防抖**：按 `(chat_id, sender_id)` 管理。有人叫到助理时等待补充消息；同一人继续说话会更新边界，新的点名会加速等待。
- **秘书巡检**：按 `chat_id` 管理。在场的普通消息暂时安静后，才进入秘书分析。
- **最后边界**：新消息替换等待中的旧事件；只有最后一条边界事件能够放行。
- **同会话单飞**：从秘书分析开始，到交给助理、不回复或异常收口为止，同一 `chat_id` 最多运行一轮秘书判断；交给助理后不再占用单飞门闩。
- **休息重计**：助理休息尚未结束时，普通秘书巡检即使到期也不得放行；普通巡检精力不足时同样保留最后边界并完整重计，点名不受精力门槛限制。不回复不会启动独立冷却。
- **离场应答**：离场时若开启对应开关，复读或密集聊天命中条件后可回复一次；发送成功后仍保持离场，并开始离场应答休息。

## 四、回复决策与发送

1. 离场应答命中时，直接生成一次性回复策略，不进入常规是否接话判断。
2. 常规群聊由秘书读取激活时重建的上下文，产出 `SecretaryDecision`。
3. `should_reply=False`：停止本事件，记录不回复，并释放秘书单飞；当前版本不再启动独立的 `no_reply_cooldown`。
4. `should_reply=True`：把本事件交给 AstrBot 助理并立即释放秘书单飞；正式上下文来自 `ConversationLedger`，工作账本只作为临时提醒。
5. 助理被调用后启动 `waiting_time` 对应的助理休息；发送成功后，离场应答保持离场，其他群聊回复进入或保持在场，并完成能量结算。

## 五、异常与离场

- 闭嘴或掌嘴：清除该会话的全部等待事件，旧事件全部 KILL。
- 在场超时：转为离场并清除等待事件。
- 防抖计时或秘书处理异常：停止对应事件并释放同会话秘书调度。
- 复读、跟风、密集发言：不会自动进场；仅在开启对应离场应答且命中条件时回复一次。

## 六、关键文件

- [`core/conversation_ledger.py`](../core/conversation_ledger.py)：正式会话历史。
